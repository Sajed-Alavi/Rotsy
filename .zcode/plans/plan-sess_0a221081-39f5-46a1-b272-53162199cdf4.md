# Plan: Scanner DB polish + Real Monitoring + UI simplicity

## Your 4 asks

### 1. Scanner DB updates — show date + progress + delete old
**Currently**: `handle_scanner_db_update` runs `trivy image --download-db-only` blindly, no progress, no date, no cleanup of the old DB. Old DBs accumulate in `/root/.cache/trivy/db/` and grype cache.

**Changes**:
- **`backend/app/services/scanners.py`**:
  - Add `db_status()` → returns `{trivy: {version, created_at, size_bytes}, grype: {...}}` by parsing the cache directory (`~/.cache/trivy/db/metadata.json` for Trivy; grype's `~/.cache/grype/db/`). The `metadata.json` Trivy writes contains `Version`, `CreatedAt`, `NextUpdate`, `DownloadedAt` — exactly "what day it's for".
  - `update_scanner_dbs()` — capture stdout line-by-line via streaming subprocess (trivy emits `Downloading security DB... [xxMB/yyMB]`), parse progress percent, call `progress()`.
  - On success: delete the previous DB version (Trivy stores old as `db/trivy.db.bak` or versioned — clean up). Grype stores one DB at a time, naturally replaced.
- **`backend/app/routers/scan.py`**: 
  - `GET /scan/db-status` → calls `db_status()`, returns the date each DB is for + size + last update.
- **`job_handlers.handle_scanner_db_update`**: now passes `progress()` from the streaming parser.

### 2. Metrics page — wrong, replace with real monitoring
**Currently**: shows only storage snapshots over time (total bytes per repo). That's useful but it's *storage accounting*, not *monitoring*.

**What "real monitoring" means here** (Nexus exposes these):
- **Health checks** (`/status/check`): CPU count, blobstore quota, blobstore ready, file path, scheduler, deadlock, JVM health, ECR token freshness — each has `healthy: bool` + a message.
- **Blobstore stats** (`/blobstores`): name, type, blobCount, totalSizeInBytes, availableSpaceInBytes, unavailable flag — real disk usage with free space.
- **Repo activity** (already stored as `Metric` rows but better framed): components/assets count over time, storage trend.
- **System status**: Nexus version (from `/status`), anonymous realm, admin creds status (security).

**Changes**:
- **`backend/app/routers/metrics.py`** overhaul:
  - `GET /metrics/overview` → already exists, keep but reframe as "storage snapshot".
  - `GET /metrics/health` (NEW) → returns the health-check dict from Nexus (`/status/check`).
  - `GET /metrics/blobstores` (NEW) → blobstore list with size/free/blob-count.
  - `GET /metrics/system` (NEW) → version, anonymous enabled, security warnings.
  - `GET /metrics/{repo}/timeseries` → keep (storage + asset count trend).
- **`frontend/src/features/metrics/MetricsPage.jsx`** rewrite:
  - **Health section**: grid of health check tiles, color-coded (green/red).
  - **Blobstore section**: progress bars for disk usage (used/total/free).
  - **Storage trend** (existing): per-repo timeseries chart — reframed as "storage growth", not "the metric".
  - **System info**: version + security warnings card.
