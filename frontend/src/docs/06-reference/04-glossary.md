# Glossary

**Asset** — a single file in Nexus: a layer blob, a manifest, a jar. One image is many assets.

**Baseline** — an image recorded in the ledger as pre-existing history. Never auto-scanned. See [The ledger and baseline](/docs/the-ledger-and-baseline).

**Blobstore** — the physical storage backing one or more repositories, file or S3. Blobs are shared, so repository sizes do not sum to blobstore usage.

**Code Quality** — the global section for running and browsing SonarQube analysis against any synced GitHub/GitLab repository and branch, independent of Project grouping. See [Automatic analysis and Smart Insights](/docs/automatic-analysis-and-insights).

**Component** — Nexus's unit of a published thing: one image tag, one jar version. Made of assets.

**Compaction** — the Nexus task that reclaims disk from deleted components. Until it runs, deletions free nothing.

**Connector port** — the per-repository port on which Nexus serves the Docker Registry v2 API. Discovered, never configured.

**CVE** — Common Vulnerabilities and Exposures identifier, e.g. `CVE-2024-3094`.

**Finding** — one vulnerability in one package in one scan report, or one issue/hotspot in one SonarQube analysis run, depending on context.

**GitHub App** — how Rotsy connects to GitHub: one App per Rotsy instance, installed per organization or account, created automatically via GitHub's App Manifest flow. See [Connecting GitHub](/docs/connecting-github).

**Grype** — Anchore's vulnerability scanner. One of the two backends.

**Job** — a unit of background work in the Redis-backed queue, with live progress over SSE.

**Ledger** — `scan_image_ledger`, the durable record of every known image and its state.

**Manifest** — the registry document describing an image: its layers and configuration. Fetching it is how an image is identified without pulling it.

**Manifest digest** — the content hash of a manifest. What the ledger compares, so a re-pushed tag is correctly seen as new.

**Personal Access Token (GitLab)** — the credential Rotsy uses to connect to GitLab, either account-level (one token, every repository it can see) or repository-level (one token, one repository). See [Connecting GitLab](/docs/connecting-gitlab).

**Project** — groups a GitHub/GitLab repository together with its Nexus artifacts, and carries a Health Score. Distinct from Code Quality, which analyzes repositories independent of Project grouping.

**Project Health Score** — a 0–100 number per Project, deducting fixed amounts for a failing quality gate, vulnerabilities, bugs, low coverage, high duplication, and recent Smart Insights. See [Automatic analysis and Smart Insights](/docs/automatic-analysis-and-insights).

**Quality Gate** — SonarQube's pass/fail verdict on an analysis, against a set of threshold conditions (e.g. no new Blocker issues, coverage above X%).

**Report** — the result of one scanner run against one image. Two scanners produce two reports.

**Scan target** — a repository enabled for scanning.

**Smart Insight** — a deterministic, evidence-backed observation generated by comparing two consecutive SonarQube analyses of the same repository/branch (e.g. "coverage dropped"). Never inferred without the exact numbers that triggered it.

**SonarQube project (per-branch)** — on SonarQube Community Edition, a non-default branch gets its own auto-provisioned Sonar project, since Community Edition can't analyze more than one branch under a single project. Created and reused automatically; never something you create yourself.

**SSE** — Server-Sent Events, the one-way streaming protocol used for live job progress.

**Stale database** — a vulnerability database older than five days.

**Static analysis** — reading an image as data over the registry API, never executing it. See [The static-only guarantee](/docs/static-only-guarantee).

**Trivy** — Aqua Security's vulnerability scanner. The other backend.
